## Decisiones tomadas

1. **Google nativo con `expo-auth-session/providers/google` + `useIdTokenAuthRequest`:** alineado con la doc de Expo SDK 57; el `id_token` se intercambia con `supabase.auth.signInWithIdToken` (mismo patrón que Apple), sin clonar el redirect OAuth web.
2. **Apple solo en iOS:** cumple la exigencia de Apple cuando se ofrece Google en iOS; errores de proveedor no habilitado se muestran como mensaje claro, sin crash.
3. **Handler con inyección de dependencias:** facilita tests TS (401 / 409 / 200) sin mocks de módulo ESM.
4. **Auth del borrado:** Bearer token del usuario verificado con `getUser(token)` en cliente anon; la RPC corre con cliente autenticado como ese usuario para que `auth.uid()` funcione; el borrado real usa service role en servidor.
5. **Confirmación explícita en mobile:** escribir `ELIMINAR` antes de llamar a la API.

## Riesgos o dudas

- Google nativo requiere **tres client IDs** (iOS, Android, Web) distintos del flujo redirect web; sin ellos el botón muestra hint de configuración.
- `EXPO_PUBLIC_SITE_URL` debe apuntar al backend Next.js (Railway dev) para que mobile llame al borrado; CORS no aplica (POST simple), pero el dominio debe ser alcanzable desde el dispositivo.
- Borrar cuenta elimina `auth.users` → cascade `profiles`; `players.profile_id` queda NULL (testeado en SQL 041).

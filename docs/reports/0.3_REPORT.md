## 1. Resumen

Importador de torneos adultos desde Excel/CSV en la pantalla **Equipos del torneo**: plantilla `.xlsx` descargable, análisis server-side con IA (solo encabezados + 10 filas de muestra), vista previa con mapeo manual editable, importación completa en servidor reutilizando validaciones de roster existentes. Torneos `is_youth = true` bloqueados con mensaje explícito.

## 3. Decisiones tomadas

1. **Ubicación UI:** panel en `/equipos` (listado del torneo), no en inscribir un solo equipo — el caso de uso es migración masiva de varios equipos/jugadores.
2. **Límite de archivo:** **2 MB** (`EXCEL_IMPORT_MAX_FILE_BYTES`). Documentado en UI y reporte.
3. **Seguridad IA:** `callAI` recibe solo encabezados + muestra; confirmación reenvía el archivo al servidor (guardado en estado cliente) para procesar el cuerpo completo sin mandarlo a Anthropic.
4. **Teléfono:** se persiste con update post-`create_players_and_add_to_roster_bulk` (el RPC bulk no incluye teléfono).
5. **Sobrecupo:** advertencia no bloqueante vía `buildRosterImportOverCapacityWarning`, igual que roster-import.

## 4. Flujo (texto)

1. Admin abre **Torneo → Equipos** (`/equipos`).
2. Descarga **plantilla .xlsx** (columnas: Equipo, Jugador, Dorsal, Teléfono).
3. Sube `.xlsx` o `.csv` → **Analizar archivo**.
4. Servidor lee encabezados + 10 filas, llama IA → propone mapeo JSON.
5. Admin revisa selects de mapeo + tabla previa (10 filas mapeadas).
6. **Confirmar importación** → servidor parsea archivo completo, crea equipos/inscripciones/jugadores, muestra resumen y filas omitidas.

**Torneo infantil (`is_youth`):** panel muestra aviso ámbar y no permite subir archivo.

### Corrección post-revisión: script `test` y conteo de suites

**Hallazgo:** al agregar `src/lib/teams/excel-import/*.test.ts`, la shell expandía
`src/lib/teams/**/*.test.ts` con semántica de un solo nivel **antes** de que Node
viera el patrón. Los `.test.ts` en `teams/` (sin subcarpeta) dejaron de ejecutarse
sin error: `npm test` pasaba de **213 tests / 96 suites** (main) a **207 / 93**
(-15 tests legacy en teams + 9 nuevos excel-import = -6 neto).

**Fix:** `package.json` → `"test"` envuelto en `bash -O globstar -c "..."` para que
`**` sea recursivo de forma estable en todos los directorios listados.

**Cálculo esperado vs real (base actual post-1.1 y 0.4):**

| Fuente | tests | suites |
|--------|------:|-------:|
| `origin/main` (incl. 1.1 + 0.4) | 217 | 98 |
| Nuevos `excel-import/*.test.ts` | +9 | +6 |
| **Total esperado** | **226** | **104** |
| **`npm test` tras fix + rebase** | **226** | **104** |

*(Sobre la base antigua pre-1.1 era 213 + 9 = 222 / 102.)*

Archivos excel-import nuevos: `column-mapping` (3), `parse-column-mapping-response` (2),
`parse-spreadsheet` (3), `validate-import` (1).

**Railway / CI:** `railway.toml` solo define healthcheck de deploy; **`npm test` no corre
en el pipeline de Railway** (solo `npm run build` vía Nixpacks). El fix aplica igual en
local y en cualquier job futuro que invoque `npm test`.

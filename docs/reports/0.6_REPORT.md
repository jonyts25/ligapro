1. **Ruta web `mis-partidos` no existe aún** en `src/app/(protected)/organizaciones/[organizationId]/mis-partidos`. La consulta mobile replica el diseño del inventario 0.6: `match_officials` filtrado por `profile_id` + lecturas de `matches`, `season_teams` y `field_reservations` (mismo patrón que `getMatchSchedulingDetails` / `loadSeasonTeamNames` / `loadReservations` en `src/lib/fixtures/queries.ts`).

2. **Tipos compartidos vía alias TS** `@ligapro/database` → `../src/types/database.ts` (ADR 0019 opción 1). Sin script de copia: el repo sigue siendo un solo clone.

3. **`react-native-url-polyfill`** añadido en el cliente Supabase (requerido en React Native).

4. **Auth con React context** (`AuthProvider`) en lugar de depender de cookies SSR de la web.

## Pruebas manuales para Jonathan

1. **Variables:** `cd mobile && cp .env.example .env` — pegar URL y anon key de **ligapro-dev** (mismas que `NEXT_PUBLIC_SUPABASE_*` en web).
2. **Arranque:** `npm install && npm start` — abrir en Expo Go o simulador.
3. **Login:** Usuario que exista en Auth y tenga perfil vinculado (p. ej. árbitro/anotador de prueba). Debe entrar sin error y redirigir a «Mis partidos».
4. **Mis partidos:** Si tiene filas en `match_officials`, ver tarjetas con **rival** (local vs visitante), **fecha/hora** (CDMX si hay reserva), **cancha/sede**, **rol**, **estado de asignación** y **estado del partido**. Si no tiene asignaciones, mensaje «No tienes partidos asignados…».
5. **RLS:** Probar con usuario A (con asignaciones) y usuario B (sin asignaciones). B no debe ver partidos de A.
6. **Sesión:** Cerrar app y reabrir — debe mantener sesión (secure-store). Pulsar **Salir** — debe volver a login.
7. **Web sin regresión:** `npm run build` en raíz — debe seguir compilando; desplegar branch en Railway preview opcional y confirmar `/api/health`.

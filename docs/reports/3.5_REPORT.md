## Decisiones tomadas

1. **Shared sin URLs firmadas:** `fetchCaptainRosterCore` devuelve `photoPath`; web sigue resolviendo signed URLs en el wrapper; mobile usa `resolvePlayerPhotoUrl` + `can_view_player_photo`.
2. **Tabs plantel/partidos** en una sola pantalla (como el hub web de `/mi-equipo/[seasonTeamId]`) en lugar de rutas separadas.
3. **Reprogramación, finanzas, credencial PDF:** fuera de alcance explícito — quedan en web para un paso futuro.
4. **Marcas de pago del plantel web:** no incluidas en mobile (control informal de capitán; no esencial para este paso).

## Hallazgo: hueco de autorización en RPCs de deduplicación e invitación

**Problema:** `find_potential_duplicate_player` e `invite_player_to_roster` (paso 3.4) solo permitían `organization_owner/admin`. Un capitán podía dar de alta con `create_player_and_add_to_roster` pero **no** podía deduplicar por teléfono ni invitar a reclamar perfil desde mobile (ni desde web captain, que tampoco tenía dedup).

**Corrección** (`20261004100000_captain_roster_invite_dedup.sql`):
- `invite_player_to_roster`: también autoriza `is_active_captain_or_vice_of_season_team` del plantel del jugador.
- `find_potential_duplicate_player`: también autoriza capitán/subcapitán activo en la organización.
- Política `captain_invitations_select_team_leader`: el capitán puede leer el token pendiente para compartir el enlace de invitación.

**Test:** `045_captain_roster_invite_dedup.sql`.

No se encontró hueco adicional de RLS en `season_team_players` / `season_rules` para capitanes (ya existían políticas `select_team_leader`).

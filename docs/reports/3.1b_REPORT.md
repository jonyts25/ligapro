## Decisiones tomadas

1. **`app.config.ts` en lugar de `app.json`.** Un JSON estático no puede leer `EXPO_PUBLIC_GOOGLE_IOS_CLIENT_ID`. La config dinámica de Expo (SDK 57) evalúa `process.env` y el CLI carga `.env` antes de resolverla (`npx expo config` lo confirmó).
2. **El reversed client ID va en `ios.scheme`, no en el `scheme` raíz.** En SDK 57, `ios.scheme` se fusiona con el scheme de primer nivel solo en iOS. El scheme `ligera` (Expo Router) se queda en la raíz. Android no recibe el scheme del cliente iOS: la guía actual de Google marca los custom URI schemes como no soportados en Android.
3. **También se registra `mx.ligera.app` en `ios.scheme`.** En `expo-auth-session` 57 (`providers/Google.ts`), el redirect nativo de builds standalone/bare es `` `${Application.applicationId}:/oauthredirect` ``. La forma `com.googleusercontent.apps.${guid}` está comentada en ese archivo. Sin el scheme del bundle ID, iOS no puede reabrir la app cuando el redirect es el que la librería emite hoy. La guía de OAuth para apps instaladas de Google acepta las dos formas: DNS inverso propio (`mx.ligera.app:/…`) o reversed client ID.
4. **El placeholder de `.env.example` no se registra como scheme.** Si el valor no termina en `.apps.googleusercontent.com`, es el placeholder, o no cumple el patrón de scheme de Expo (`^[a-z][a-z0-9+.-]*$`), se omite. El bundle ID sí queda siempre.
5. **En web solo se exige el client ID web.** El prompt cubre iOS y Android. En `Platform.OS` distinto de esos dos, el ID de la plataforma es el web.

## Riesgos o dudas

1. **Redirect de la librería vs reversed client ID.** El scheme que el prompt pide (reversed client ID) quedó registrado. El redirect que `expo-auth-session` 57 emite en standalone/bare sigue siendo `mx.ligera.app:/oauthredirect`. Si el cliente OAuth de iOS en Google Cloud solo autoriza el reversed client ID, el login puede fallar con `redirect_uri_mismatch` aunque el scheme exista. Corregirlo implica pasar otro `redirectUri` al provider: es cambio de flujo, fuera de este paso.
2. **Scheme y bundle ID son de build time.** Un OTA no los actualiza. Hay que rehacer el binario si cambia el client ID de iOS.
3. **No hay prueba en dispositivo.** Typecheck, expo-doctor y `expo export` no abren el flujo de Google.

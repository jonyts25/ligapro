# Reporte paso 3.2 — Entrada por persona (mobile) + arreglo RLS en players

## Resumen

Se corrigió el hueco de RLS en `players` con la política aditiva `players_select_self` (`profile_id = auth.uid()`), lo que desbloquea lecturas propias del jugador reclamado (incluido el INNER JOIN de `getCaptainTeamsViaRoster` en web). Se añadió `getPersonContexts` en `src/lib/shared/` y la pantalla de inicio mobile (`index.tsx`) agrupa administración, partidos por arbitrar y equipos como jugador.

## Bug de RLS encontrado (y alcance del fix)

**Problema:** `players` solo tenía `players_select_member` (`is_member_of(organization_id)`). Un jugador/capitán reclamado (paso 3.4) vincula `profile_id` pero **no** entra a `organization_members`. El cliente Supabase no podía leer su fila en `players`.

**Impacto en producción (preexistente):** `getCaptainTeamsViaRoster` (`src/lib/auth/get-captain-teams.ts`) usa `players!inner(profile_id)`. Sin fila visible en `players`, el JOIN devolvía 0 filas y el portal de capitán web caía al fallback degradado (`teamName: "Mi equipo"`). **Este cambio arregla web y mobile**, no es exclusivo de la app.

**Fix:** política aditiva `players_select_self` — Postgres combina SELECT con OR; `players_select_member` intacta para staff.

## 1. Resumen

Se investigó el drift entre `ligapro-dev` (tiene aplicada `20260809201303_cotizador_tier_teams_jornada_v2`) y el repo (solo `20260808200000_cotizador_tier_teams_jornada.sql`, v1). **No se encontró diferencia de esquema real entre v1 y el estado inferido de dev**: tipos generados, código de la app, ADRs y test SQL 030 coinciden con v1. Se añadió el archivo v2 como migración de reconciliación idempotente (reafirmación de grants), alineada con el patrón de `20260827100000_harden_create_player_grants.sql`. **No se aplicó a Supabase.**

## 3. Decisiones tomadas

1. **v2 = reconciliación, no reimplementación.** El reporte `PR_REVIEW_MERGE_4_FEATURES_REPORT.md` ya documentaba que v2 se aplicó vía MCP sin archivo en repo. La rama `origin/cursor/cotizador-tier-jornada-9bf5` contiene un diseño **distinto** (`20260809100000_season_teams_status_void_match.sql`: `set_organization_plan_tier` retorna `void`, walkover winner/loser, `jornada_summaries.content` jsonb, RPCs `bulk_create_*`, etc.) que **no coincide** con dev ni con el código actual — se descartó como fuente de v2.

2. **Sin test SQL nuevo.** Ya existe `supabase/tests/030_cotizador_tier_teams_jornada.sql`, que cubre plan_tier, premium gate, void por retiro y el bundle v1. v2 solo reafirma grants; no aporta objetos nuevos que requieran test adicional.

3. **MCP Supabase no disponible** (timeout de autenticación). Toda conclusión se basó en evidencia indirecta del repo; ver sección 7.

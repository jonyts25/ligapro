# Reporte paso 3.4 — Reclamo de perfil genérico + deduplicación por teléfono

## Resumen

Se generalizó la invitación a reclamar perfil para **cualquier** jugador sin `profile_id` (RPC `invite_player_to_roster`, sin tocar `invite_captain_to_roster`). Se añadió deduplicación **por teléfono dentro de la misma organización** con confirmación explícita del admin (`find_potential_duplicate_player`, `add_existing_player_to_roster`) y UI en el alta individual de jugador.

## Decisiones tomadas

1. **`invite_captain_to_roster` intacto** — `create_captain_player_with_invitation` sigue igual; UI admin usa `invite_player_to_roster` para todos.
2. **Comparación de teléfono con `btrim`** — no existe normalización centralizada en el proyecto; misma regla que `create_player_and_add_to_roster`.
3. **`add_existing_player_to_roster` rechaza fila existente en el mismo `season_team`** — más estricto que `add_player_to_season_team` (que reactiva inactivos); evita duplicado real en dedup.
4. **Confirmación explícita en UI** — nunca auto-enlaza; admin elige «misma persona» o «crear nuevo» (`forceCreateNew=true`).

## Pruebas manuales para Jonathan

1. En plantel de temporada, jugador **regular** sin perfil → «Invitar a reclamar su perfil» → correo → aceptar en `/invitacion/[token]` con cuenta de prueba → `profile_id` vinculado.
2. Dar de alta jugador con teléfono que ya existe en otro equipo de la **misma org** → aparece tarjeta de posible duplicado con nombre y conteo de equipos.
3. Elegir «Es alguien distinto — crear nuevo» → se crea player nuevo aunque el teléfono coincida.
4. Elegir «Es la misma persona» → se agrega el `player_id` existente al plantel sin duplicar fila en `players`.
5. Invitar capitán vía flujo legacy `create_captain_player_with_invitation` → sigue funcionando (usa `invite_captain_to_roster`).

## Riesgos o dudas

- Teléfonos mal capturados pueden generar falsos positivos; por eso la confirmación es obligatoria.
- Sin teléfono no hay dedup; nombre solo no se usa (como indica el prompt).
- Capitanes pueden invitar desde portal solo si existe UI equivalente en paso futuro.

## Resumen

Pantalla org-wide de diagnóstico para el domingo (o cualquier fecha): partidos con reserva confirmada en temporadas activas, alertas contextuales y enlace al detalle existente del partido. Solo web; sin mobile ni finanzas/suspensiones masivas.

## Migración

`supabase/migrations/20260927230000_organization_matchday.sql`:

- RPC `get_organization_matchday(p_organization_id, p_date)`
- Filtro por día local `America/Mexico_City` sobre `field_reservations.starts_at` confirmadas
- Temporadas con `visibility <> 'archived'`
- Auth: `is_member_of(organization_id)`
- Columnas extra respecto al spec mínimo: `competition_id` y `match_duration_minutes` (necesarias para links y alertas TS)

Tests SQL: `supabase/tests/036_organization_matchday.sql` (5 casos)

## Web

- Ruta: `/organizaciones/[organizationId]/jornada-en-vivo`
- Nav: **Jornada en vivo** visible para cualquier miembro (`nav-items.ts`)
- Selector de fecha (default hoy CDMX, flechas + input + “Hoy”)
- Lista responsive con escudos, hora/cancha, torneo/temporada, marcador
- Alertas solo cuando aplican (badges warning/danger)
- Cada fila enlaza a `.../torneos/.../temporadas/.../partidos/[matchId]`

## Consulta y tipos

- `src/lib/matches/live-matchday-core.ts` — fechas CDMX + `buildLiveMatchdayAlerts` (puro, testeable)
- `src/lib/matches/live-matchday-queries.ts` — `fetchOrganizationMatchday` (server)
- Tests TS: `live-matchday-queries.test.ts` (7 casos alertas + fechas)

Alertas implementadas:

| Alerta | Condición |
|--------|-----------|
| Sin árbitro confirmado | Sin referee confirmado y hora ≥ 30 min antes del inicio |
| Resultado pendiente de captura | `scheduled` y ya pasó inicio + duración |
| Disputa abierta | `has_open_dispute` |
| Pendiente de aprobación | `finished`/`walkover`, sin disputa, sin `result_approved_at` |
| Plantel sin validar | Ambos equipos 0 `played` y ya empezó |
